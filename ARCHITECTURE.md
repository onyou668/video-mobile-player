# Architecture

## Dependency boundary

```text
Host application
      |
      v
player-compose ----> player-engine-media3 ----> player-core
       |                                      ^
       +-----------> player-engine-ijk -------+
```

`PlaybackEngine` is the only interface an SDK adapter implements. `VideoPlayerController` owns engine replacement and state continuity. `VideoPlayer` renders only `PlaybackState` and emits controller commands.

`VideoContentCache` is the engine-neutral media-byte seam. Playback history is deliberately external: the host observes `PlaybackState`, stores progress in its own `PlaybackProgressStore`, and passes the saved position as `startPositionMs`. Engine adapters only receive the resolved source and start position, so engine switching cannot fork progress state.

## Engine switching

1. Read the current position and playback intent from the unified state.
2. Release the old engine and cancel its state collector.
3. Create the selected adapter and reattach the existing `Surface`.
4. Restore volume and playback speed.
5. Prepare the same source at the captured position and restore play/pause intent.

The old adapter cannot publish stale callbacks after replacement because the controller checks engine identity before accepting an emitted state.

## Cache boundary

`AppPrivateVideoPlayerCache` is the bundled media-byte adapter. It stores progressive network byte ranges in a configurable directory and does not own playback history. Local sources and HLS/DASH manifests bypass content caching. Before an engine is prepared, a supported network source is resolved to a loopback HTTP URL owned by one process-local `ProgressiveMediaProxy`; Media3 and IjkPlayer therefore consume the same cached bytes.

The proxy binds only to `127.0.0.1` and uses an unguessable per-process path token. It divides upstream content into fixed 512 KiB segments under `filesDir/video-mobile-player-cache/<sha256(mediaId)>`. A cached segment is served from disk. A missing segment is requested upstream with HTTP Range, streamed to the player while it is written to a `.part` file, then promoted to `.segment` after its length is verified. Seeking naturally requests and stores a different segment. Cache size enforcement is LRU at segment granularity.

`mediaId` is an opaque SHA-256 identity generated by the shared `MediaIdGenerator` from source type and the complete URI. Titles and authorization headers may rotate without changing the key; changing the URI creates a new identity. The adapter persists upstream length and validators in `metadata.json`, falls back to direct playback when a server does not honor byte ranges, and invalidates segment data when a fetched range proves that the upstream identity changed. HLS/DASH segment caching and encrypted/offline license management remain outside the bundled adapter; callers can configure a cache directory and extension allow-list or inject another `VideoContentCache` without changing the controller or an engine interface.

## Presentation boundary

`PortraitVideoPlayer` is a fixed portrait-only surface with no fullscreen state. `LandscapeVideoPlayer` is a controlled inline/fullscreen adapter: the caller owns `isFullscreen` and receives `onFullscreenChange`, while the component performs the Activity orientation, dialog, immersive system bars, and restoration. PiP, overlay permission, foreground services, and navigation remain host concerns and reuse the same `VideoPlayerController`.

## Extension point

A new playback SDK only needs a `PlaybackEngine` plus `PlaybackEngineFactory`. The controller accepts a factory map, so adding an engine does not change existing adapters or the state model. The bundled `rememberVideoPlayerController` intentionally registers only Media3 and IjkPlayer.

Network throughput is reported through the engine-neutral `EnginePlaybackState.networkSpeedBytesPerSecond`. Each adapter owns its native measurement strategy; the controller and Compose UI do not depend on Media3 or IjkPlayer networking APIs.

Presentation transitions never own playback state. The shared `VideoPlayerController` keeps the media session alive as the host moves the same surface between inline, fullscreen, or host-owned overlay containers.
